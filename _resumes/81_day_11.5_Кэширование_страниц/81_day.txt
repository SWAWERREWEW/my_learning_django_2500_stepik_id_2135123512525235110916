После запуска в панели djdt отображается количество кеша
Его количество может быть меньше, а количество обращений к базе данных может быть больше, чем у автора курса, потому
что в django есть защитные механизмы, не позволяющие загружать кеш для авторизованных пользователей, чтобы аноним не
увидел панель администратора, а авторизованному пользователю не отобразились чужие данные, однако если кеш вообще
появился даже 1 это уже успех и корректная работа redis в django

Для ручного кеширования страниц, можно прописать дополнительно после {% load static %}
Кешировать block content и csrf_token или любое содержимое, которое меняется для каждого пользователя ни в коем случае
нельзя для безопасности и правильной работы сайта

{% load cache %}
<!-- 500 — это время в секундах, 'sidebar' — уникальное имя ключа -->
{% cache 500 to_cache %}
    <div class="to_cache">
        <!-- данные для кеширования -->
    </div>
{% endcache %}

Существуют различные функции для управления кешом
cache.set() – сохранение произвольных данных в кэш по ключу;
cache.get() – выбор произвольных данных из кэша по ключу;
cache.add() – заносит новое значение в кэш, если его там еще нет (иначе данная операция игнорируется);
cache.get_or_set() – извлекает данные из кэша, если их нет, то автоматически заносится значение по умолчанию;
cache.delete() – удаление данных из кэша по ключу;
cache.clear() – полная очистка кэша.

    def get_queryset(self):
        women_posts_cache = cache.get('women_posts')

            cache.set('women_posts', women_posts_cache, 60)
