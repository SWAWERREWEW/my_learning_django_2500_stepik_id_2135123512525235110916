26 day = 4.3 ORM-команды для связи many-to-one

Для получения атрибутов таблицы SQL запрос не выполняется (title, slug, cat_id), а для cat формируется запрос для
формирования объекта всей привязанной модели. Судя по всему это означает, что title, slug, cat_id и т д уже
сформированные объекты.

То есть через одну модель, можно обратиться к атрибутам другой привязанной модели
In [8]: Women.objects.get(id=1)
Out[8]: <Women: Анджела>
In [9]: Women.objects.get(id=1).cat
Out[9]: <Category: Актрисы>
In [10]: Women.objects.get(id=1).cat.name
Out[10]: 'Актрисы'

Частично можно сделать и наоборот. Через привязанную модель обратиться к другой модели.
In [20]: Category.objects.get(id=1).women_set.all()
Out[20]: <QuerySet [<Women: Анджела>, <Women: КАРАБЛИК>, <Women: start_day_20>]>
In [21]: Category.objects.get(id=1).women_set.all()[0]
Out[21]: <Women: Анджела>
In [22]: Category.objects.get(id=1).women_set.all()[0].title
Out[22]: 'Анджела'

Можно отобразить записи с условием только для одного поля
Category.objects.filter(slug='aktrisy')

Можно также отобразить записи из одной таблицы с условием для одного поля привязанной таблицы. То есть отображение всех
полей таблицы Women, если их идентификаторы связаны с теми полями привязанной таблицы, у которых slug = 'aktrisy'.
Отвечая на вопросы: Какая запись таблицы Category в поле slug имеет 'aktrisy', какой у неё идентификатор и у каких
записей таблицы Women такой же идентификатор в поле cat_id
Women.objects.filter(cat__slug='aktrisy')

Можно использовать больше люкапов. Отображение по полю slug, если там есть буква 'a'.
Women.objects.filter(cat__slug__contains='a')

В таблице Women поле cat_id было заменено на поля записи с соответствующим id
В том месте, где должна стоять 1 в поле cat_id появилась первая запись таблицы Category и была продублирована в тех
местах, где тоже стояла 1

Чтобы отображались уникальные записи, а не такие дубликаты, существует лукап distinct()
Category.objects.filter(posts__slug__contains='date').distinct()
