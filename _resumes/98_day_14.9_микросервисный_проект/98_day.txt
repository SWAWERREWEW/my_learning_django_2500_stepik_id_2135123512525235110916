При остановке контейнера все добавленные данные сразу удаляются
Нужно сделать том для хранения данных

📖 Было открыто описание образа
https://hub.docker.com/_/postgres
🔍 Был найден текст по поиску "-v"
Users who wish to opt-in to this change on older releases can do so by setting PGDATA explicitly (--env PGDATA=/var/lib/postgresql/17/docker --volume some-postgres:/var/lib/postgresql). To migrate pre-existing data, adjust the volume's folder structure appropriately first (moving all database files into a PG_MAJOR/docker subdirectory).
Important Note: (for PostgreSQL 17 and below) Mount the data volume at /var/lib/postgresql/data and not at /var/lib/postgresql because mounts at the latter path WILL NOT PERSIST database data when the container is re-created. The Dockerfile that builds the image declares a volume at /var/lib/postgresql/data and if no data volume is mounted at that path then the container runtime will automatically create an anonymous volume that is not reused across container re-creations. Data will be written to the anonymous volume rather than your intended data volume and won't persist when the container is deleted and re-created.
💬 Перевод
Пользователи, желающие принять это изменение в более старых выпусках, могут сделать это, явно задав PGDATA (--env PGDATA=/var/lib/postgresql/17/docker --volume some-postgres:/var/lib/postgresql). Чтобы перенести ранее существовавшие данные, сначала соответствующим образом настройте структуру папок тома (переместив все файлы базы данных в подкаталог PG_MAJOR/docker).
Важное примечание: (для PostgreSQL 17 и более ранних версий) монтируйте том данных в /var/lib/postgresql/data, а не в /var/lib/postgresql, поскольку при монтировании по последнему пути НЕ СОХРАНЯЮТСЯ данные базы данных при повторном создании контейнера. Dockerfile, который создает образ, объявляет том в /var/lib/postgresql/data, и если по этому пути не смонтирован ни один том данных, среда выполнения контейнера автоматически создаст анонимный том, который не будет повторно использоваться при повторном создании контейнера. Данные будут записаны в анонимный том, а не в предполагаемый том данных, и не сохранятся при удалении и повторном создании контейнера.

# docker\flask_db_image\Dockerfile
FROM python:3.12-slim
RUN groupadd -r newgroup && useradd -r -g newgroup kikidon

RUN pip install flask psycopg2-binary

EXPOSE 4000

WORKDIR /app
COPY ./flask_project/site.py .

USER kikidon
ENTRYPOINT ["python", "site.py"]


➕💾🛠📁 Был создан файл
# docker\flask_db_image\flask_project\site.py

from flask import Flask
import psycopg2

app = Flask(__name__)

@app.route('/')
def index():
    conn = psycopg2.connect(dbname='mydb', user='postgres',
                            password='1234', host='dbps')
    cursor = conn.cursor()

    cursor.execute('SELECT * FROM women LIMIT 10')
    records = cursor.fetchall()

    cursor.close()
    conn.close()

    return '<h1>kikidon!</h1>' + f'{"<p>".join(map(str, records))}'

if __name__ == '__main__':
    app.run(debug=True, host='0.0.0.0', port=4000)
