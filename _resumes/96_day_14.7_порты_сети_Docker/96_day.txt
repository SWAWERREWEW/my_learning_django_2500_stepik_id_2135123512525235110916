96 day = 14.7 Работа с портами внутренней сети Docker

docker создаёт себе отдельную базу данных, а ещё создаёт свою сеть. К её контейнеры не доступны даже в локальной сети.

📦📥🌎
Установка nginx
docker pull nginx

🛠📦💾
Создание контейнера на основе nginx
docker run --rm -d --name moscow nginx

🔍📦📊
Отображение информации о контейнере в виде json файла
docker container inspect moscow

🛠📦📶
Контейнер на основе nginx запускается в своём порту 80, а его нужно связать с локальным портом 8000
docker run --rm -d -p 8000:80 --name moscow nginx

📶📦🛠
Можно указать адрес
docker run --rm -d -p 127.0.0.1:8000:80 --name moscow nginx

📖🔍📦
Команда для открытия содержимого контейнера
docker exec -it first_container bash

Был создан образ first_flask_image
cd docker

Был создан контейнер на основе образа first_flask_image с возможностью подключиться через порт 8080 и по
адресу 127.0.0.1 локальной сети и через порт 5000 сети docker, но можно было указать и другие от 1000
docker run --rm -d -p 127.0.0.1:8080:5000 --name fliask first_flask_image:first_flask_image

Другой порт сети docker больше не работает

Если контейнер будет отключен, то информация о его портах будет отсутствовать.
Эту информацию модно добавить

💾🛠
Был изменён файл
# docker\first_flask_image\Dockerfile
...
EXPOSE 4000

флаг -P может автоматически выбрать порт в сети docker для предотвращения конфликтов портов у контейнеров
docker run --rm -d -P --name fliask first_flask_image:first_flask_image

Команда для отображения информации о контейнере для поиска порта локальной сети и сети docker
docker ps
или
docker port fliask

По адресу с новым автоматически выбранным портом
http://127.0.0.1:32768/
открывается сообщение из файла
